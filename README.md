# LayMed Backend

Асинхронный REST API для платформы записи к врачам и поиска медицинских услуг. Сервис позволяет находить специалистов с фильтрацией по рейтингу, стоимости приема и опыту работы. Пользователи могут подавать заявки на получение профиля врача, проходящие ручную модерацию администратором. Администратор также модерирует медицинские предложения и разрешает споры по отзывам через механизм апелляций.

Проект написан для отработки архитектурных подходов, асинхронного стека, работы с S3, JWT, написанием тестов и вывода качества написания на сильный уровень (инвалидация кэша, версионирование токенов, модерация контента, работа с S3).

## Стек технологий

* **Ядро:** Python 3.12, FastAPI, Uvicorn, Pydantic 2 / Settings
* **Хранилище:** PostgreSQL 17 (драйвер `asyncpg`), SQLAlchemy 2.0 (AsyncSession), Alembic
* **Кэш и сессии:** Redis (`redis.asyncio`)
* **Файловое хранилище:** S3-compatible (Yandex Cloud через `aioboto3`), Pillow
* **Безопасность:** JWT (OAuth2 Bearer, HttpOnly Refresh Cookies), SlowAPI (Rate Limiting)
* **Качество и тесты:** Pytest (pytest-asyncio, HTTPX, Fakeredis), Ruff, Pyright, uv

## Архитектура и структура кода

Проект организован по **модульному** принципу:

```text
src/
├── core/              # Конфигурация, безопасность, зависимости, логгер, миграции
├── services/          # Инфраструктурные сервисы (S3 storage, работа с картинками, модераци)
├── common/            # Базовые схемы, общие enum и обработчик ошибок
└── modules/           # Изолированные бизнес-фичи:
    └── {feature}/     # users, doctors, offers, bookings, reviews, cities...
        ├── router.py      # HTTP-эндпоинты
        ├── service.py     # Бизнес-логика, транзакции БД, работа с кэшем
        ├── schemas.py     # Pydantic-схемы
        ├── models.py      # SQLAlchemy-модели
        └── exceptions.py  # Исключения
```

**Сквозной поток запроса:**

`HTTP Request` ➔ `SlowAPI (Rate Limit)` ➔ `FastAPI Router` ➔ `Auth \ Permission Dependencies` ➔ `Feature Service` ➔ `PostgreSQL / Redis / S3` ➔ `Pydantic Response`

## Ключевые инженерные решения

### 1. Cброс сессий через `token_version`

Для инвалидации украденных токенов или при смене пароля используется поле `token_version` в модели пользователя. При смене пароля счетчик инкрементируется, и все старые токены моментально перестают проходить валидацию в зависимостях FastAPI.

### 2. Детерминированное кэширование и автосброс в Redis

* Списки врачей, предложений и справочники кэшируются с префиксными ключами (например, `doctors:list:*`, `specialties:items:*`).
* При любых мутациях (добавление отзыва, смена цены услуги, редактирование профиля) сервис инвалидирует связанные ключи, предотвращая рассинхрон данных.
* Текущий пользователь кэшируется по ключу `users:current:{email}` для снижения нагрузки на БД при частых проверках авторизации.

### 3. Бизнес-логика модерации контента

* Публичные пользователи видят только одобренных врачей и услуги (`APPROVED`).
* **Защита от подмены:** если врач меняет уже опубликованное и проверенное предложение, оно автоматически сбрасывается в статус `PENDING` и отправляется на повторную модерацию.
* **Арбитраж отзывов:** реализовано правило «1 пациент = 1 отзыв врачу». Врач не может удалить отзыв сам, но может подать апелляцию. Администратор в панели решает: отклонить жалобу или скрыть отзыв. При удалении отзыва фоном пересчитываются `rating_avg` и `reviews_count` врача.

### 4. Пайплайн безопасной обработки медиа (Pillow + S3)

* Защита от `DecompressionBombError` и валидация реальных MIME-типов и сигнатур файлов.
* Аватары автоматически кадрируются в квадрат, ресайзятся до 400×400, конвертируются в RGB и сжимаются в JPEG.
* Фотографии предложений масштабируются до ширины 1200px перед асинхронной загрузкой в S3 (`aioboto3`) с генерацией уникальных UUID-ключей.

## Тестирование

Кодовая база покрыта интеграционными (API) и модульными тестами. Для изоляции тестов от окружения используются отдельная тестовая БД PostgreSQL и `fakeredis`:

```bash
# Запуск всех тестов
uv run pytest

# Запуск с детальным выводом
uv run pytest -v

# Запуск только API-тестов (проверка бизнес-логики, прав и кэша)
uv run pytest tests/api
```

## Локальный запуск

### 1. Быстрый подъем через Docker Compose

Поднимает приложение, PostgreSQL 17 и Redis одной командой:

```bash
cp .env.example .env
docker compose up --build -d
```

API будет доступен по адресу `http://localhost:8000/docs`.

### 2. Запуск для локальной разработки (uv)

```bash
# Установка окружения
uv sync

# Настройка переменных окружения
cp .env.example .env

# Применение миграций БД
uv run alembic upgrade head

# Запуск dev-сервера
uv run uvicorn main:app --reload
```
